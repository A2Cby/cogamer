# 🧠 Система сохранения контекста диалога

## 📋 Описание проблемы

При работе игрового AI ассистента **Cogamer** происходило переполнение контекста каждые ~8 минут, что приводило к необходимости перезапуска соединения. Однако при перезапуске ассистент полностью забывал предыдущий диалог и начинал "с чистого листа", что нарушало преемственность общения с игроком.

## ✅ Реализованное решение

### Основная идея
Система автоматически сохраняет **последние 3 пары реплик** (игрок + ассистент) перед каждым переподключением и восстанавливает их при новом запуске, обеспечивая бесшовный переход между сессиями.

---

## 🔧 Технические детали реализации

### 1️⃣ Новые методы в классе `GlobalContext`

#### `get_recent_conversation(num_pairs=3)`
```python
def get_recent_conversation(self, num_pairs: int = 3) -> list:
    """Возвращает последние N пар реплик (игрок-ассистент)"""
```
- Извлекает последние `num_pairs * 2` сообщений из истории диалога
- По умолчанию возвращает последние 3 пары (6 сообщений)
- Возвращает пустой список, если история пуста

#### `save_conversation_context(filepath)`
```python
def save_conversation_context(self, filepath: str = "data/conversation_context.json"):
    """Сохраняет последние 3 пары реплик в JSON файл"""
```
- Сохраняет:
  - Последние 3 пары реплик (6 сообщений)
  - Название игры
  - Категорию
  - Временную метку сохранения
- Файл сохраняется в формате JSON с кодировкой UTF-8
- Автоматически создает папку `data/`, если её нет

#### `load_conversation_context(filepath)`
```python
def load_conversation_context(self, filepath: str = "data/conversation_context.json") -> dict:
    """Загружает сохраненный контекст диалога из JSON файла"""
```
- Загружает контекст из файла при его наличии
- Возвращает пустой словарь при ошибке или отсутствии файла
- Обрабатывает исключения без прерывания работы программы

---

### 2️⃣ Изменения в методе `startup()`

При инициализации WebSocket соединения:

1. **Загружается сохраненный контекст** из `data/conversation_context.json`
2. **Формируется расширенная системная инструкция**, включающая:
   ```
   --- КОНТЕКСТ ПРЕДЫДУЩЕГО ДИАЛОГА ---
   Вот последние реплики из нашего предыдущего разговора:

   Игрок: [текст реплики]
   Ассистент: [текст ответа]
   ...

   Продолжай диалог естественно, учитывая этот контекст.
   --- КОНЕЦ КОНТЕКСТА ---
   ```
3. **Передается в Gemini** вместе с основной системной инструкцией

Это позволяет ассистенту "вспомнить" предыдущий контекст и продолжить диалог естественным образом.

---

### 3️⃣ Изменения в методе `receive_audio()`

#### Отслеживание ответов ассистента
Теперь метод извлекает текстовые части ответов ассистента из потока:
```python
text_part = (
    response_dict
    .get("serverContent", {})
    .get("modelTurn", {})
    .get("parts", [{}])[0]
    .get("text")
)
```

И автоматически добавляет их в историю диалога:
```python
if text_part and text_part.strip():
    self.global_context.add_message("assistant", text_part.strip())
```

#### Сохранение контекста перед переподключением
При достижении интервала переподключения (каждые 7 минут):

1. **Логируется событие**: `"Время переподключения. Сохраняем контекст диалога..."`
2. **Вызывается** `save_conversation_context()` — сохранение в файл
3. **Выполняется переподключение** к WebSocket
4. **Вызывается** `startup()` — который загружает и восстанавливает контекст
5. **Логируется завершение**: `"Переподключение завершено с восстановлением контекста"`

## 🚀 Преимущества решения

1. ✅ **Бесшовность** — игрок не замечает переподключения
2. ✅ **Сохранение контекста** — ассистент "помнит" последние 6 реплик
3. ✅ **Автоматизация** — не требует вмешательства пользователя
4. ✅ **Отказоустойчивость** — обработка ошибок при чтении/записи файла
5. ✅ **Минимальные изменения** — затронуты только необходимые компоненты
6. ✅ **Логирование** — все действия записываются в лог для отладки

## 🎯 Как это работает в реальном времени

### Сценарий использования:

1. **0:00** — Игрок запускает Cogamer, начинает играть и общаться с ассистентом
2. **0:30** — Игрок: "Как пройти этот уровень?"
3. **0:31** — Ассистент: "Попробуй использовать щит..."
4. **1:00** — Игрок: "Спасибо! А что дальше?"
5. **1:01** — Ассистент: "Иди налево к сундуку..."
6. **7:00** — ⚡ Автоматическое переподключение:
   - Сохраняются последние 6 реплик в файл
   - Разрывается старое соединение
   - Создается новое соединение
   - Контекст загружается и передается ассистенту
7. **7:01** — Игрок продолжает диалог, ассистент "помнит" контекст! 🎉

## 🔍 Отладка и мониторинг

### Логи для отслеживания работы системы:

1. **При сохранении контекста:**
   ```
   INFO - Контекст диалога сохранен в 'data/conversation_context.json'
   ```

2. **При загрузке контекста:**
   ```
   INFO - Контекст диалога загружен из 'data/conversation_context.json'
   INFO - Восстановлено 6 реплик из предыдущего диалога
   ```

3. **При переподключении:**
   ```
   INFO - Время переподключения. Сохраняем контекст диалога...
   INFO - Переподключение завершено с восстановлением контекста
   ```

4. **При добавлении ответа ассистента:**
   ```
   INFO - Ответ ассистента добавлен в историю: Попробуй использовать щит в момент его атаки...
   ```

## 🛠️ Настройка параметров

### Изменение количества сохраняемых реплик

В методе `save_conversation_context()` измените параметр:
```python
"recent_conversation": self.get_recent_conversation(num_pairs=5)  # Сохранять 5 пар вместо 3
```

### Изменение пути к файлу контекста

По умолчанию: `data/conversation_context.json`

Можно изменить при вызове:
```python
self.global_context.save_conversation_context("custom_path/context.json")
```

### Изменение интервала переподключения

В классе `Agent`:
```python
RECONNECTION_INTERVAL = 60*7  # 7 минут (текущее значение)
RECONNECTION_INTERVAL = 60*10  # Изменить на 10 минут
```
